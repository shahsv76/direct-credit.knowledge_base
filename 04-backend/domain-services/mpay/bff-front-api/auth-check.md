# POST auth/check (BFF)

## Описание

| Тип запроса | Название метода | Описание метода                                                                                                                                       | URL                                 | Тип  |
| ----------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- | ---- |
| POST        | auth/check      | Метод-оркестратор проверки анкеты. Принимает данные пользователя, валидирует их, запускает скоринг и генерирует токен для следующего шага (ввод СМС). | `/api/widget.php?action=auth/check` | SYNC |

## Входные параметры

### Header
| Название                                     | Тип | Обязательность | Описание                                                    | Пример |
| -------------------------------------------- | --- | -------------- | ----------------------------------------------------------- | ------ |
| 🔗 [Общие заголовки BFF](./common-headers.md) | —   | —              | См. общую страницу (включая `auth`, `Cookie`, `User-Agent`) | —      |

### URL (params)
| Название   | Тип    | Обязательность | Описание                        | Пример        |
| ---------- | ------ | -------------- | ------------------------------- | ------------- |
| `action`   | String | Да             | Имя экшена                      | `auth/check`  |
| `json`     | String | Да             | Флаг формата ответа (JSON)      | `Y`           |
| `order_id` | String | Да             | Уникальный идентификатор заказа | `0abfb32e...` |

| Название                       | Тип     | Обязательность | Описание                                                  | Пример           |
| ------------------------------ | ------- | -------------- | --------------------------------------------------------- | ---------------- |
| `isBotEnabled`                 | Boolean | Да             | Флаг, указывающий на активность бота (антифрод)           | `false`          |
| `phone`                        | Object  | Да             | Блок данных о телефоне, паспорте и доходе                 | `{...}`          |
| `phone.phone_mobile`           | String  | Да             | Маскированный номер телефона                              | `(***) ***-2211` |
| `phone.serial_number_passport` | String  | Да             | Серия и номер паспорта                                    | `1111 111111`    |
| `phone.monthly_income`         | String  | Да             | Ежемесячный доход                                         | `100000`         |
| `sms_code`                     | String  | Да             | Код из СМС (в текущем сценарии может передаваться пустым) | `111111`         |
| `ad_subscribe`                 | Boolean | Да             | Флаг согласия на рекламную рассылку                       | `true`           |
| `juicy_score`                  | String  | Да             | Токен антифрод-системы JuicyScore                         | `w.202610...`    |
| `data_token`                   | String  | Да             | Зашифрованный токен устройства (собирается на фронте)     | `eyJkYXRh...`    |

## Коды ответа
**Успешные ответы:**
| Код ответа | Описание | Причина                                                      |
| ---------- | -------- | ------------------------------------------------------------ |
| `200`      | OK       | Анкета успешно проверена. Данные валидны, скоринг рассчитан. |

🔗 Все коды ошибок (400, 401, 403, 422, 500, 502, 504) и их причины описаны на странице [Общие коды ответов BFF](./common-errors.md).

## Внутренние вызовы (Оркестрация)
При выполнении метода BFF обращается к следующим компонентам mPay:
*   **External anti fraud** — проверка токена `juicy_score`.
*   ⏳ **mpay-scoring** — расчет доступных кредитных программ.
*   ⏳ **Authentication** — валидация данных клиента (паспорт, телефон).

## Логика работы
1. **Аутентификация:** BFF валидирует заголовок `auth` (Bearer-токен). Если токен недействителен — возвращается ошибка `401`.
2. **Проверка антифрода:** BFF анализирует токены `juicy_score` и `data_token`.
3. **Оркестрация:** BFF запрашивает расчет лимитов в сервисе `mpay-scoring` и валидирует данные в `Authentication`.
4. **Формирование ответа:** BFF возвращает результат проверки (`result: true`), сгенерированный токен для следующего шага (`sms_code`) и команду перехода (`redirect_step: step/1`).
