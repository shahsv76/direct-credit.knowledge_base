## Описание
| Тип запроса | Название метода | Описание метода                                                                                                   | URL                     | Тип  |
| ----------- | --------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------- | ---- |
| POST        | ContractReadV2  | Возвращает карточку договора для v2-флоу по идентификатору заявки, включая график платежей и банковские реквизиты | `/api/v2/contract/read` | SYNC |

### Body
| Название                | Тип    | Обязательность | Описание                                                                                    | Пример         |
| ----------------------- | ------ | -------------- | ------------------------------------------------------------------------------------------- | -------------- |
| `Meta.AccountRequestID` | String | Да             | Идентификатор заявки на кредит, по которому нужно получить договор                          | `12345`        |
| `Meta.ClientID`         | String | Нет            | Идентификатор клиента. В логике метода не используется — данные клиента берутся из сессии   | `client-123`   |
| `Meta.PartnerID`        | String | Нет            | Идентификатор партнёра. В логике метода не используется — данные партнёра берутся из сессии | `dcpay-mobile` |

> ℹ️ Регистр названий полей не важен: `Meta` и `meta` обрабатываются одинаково.

## Коды ответа
| Код ответа | Описание              | Причина                                                                         |
| ---------- | --------------------- | ------------------------------------------------------------------------------- |
| `200`      | OK                    | Карточка договора сформирована                                                  |
| `400`      | BAD_REQUEST           | В сессии отсутствуют данные клиента или график платежей пуст                    |
| `500`      | INTERNAL_SERVER_ERROR | Ошибка Accounting Reader или Schedule Reader; ошибка чтения тела запроса/ответа |

🔗 *Все общие коды ошибок см. на странице [Общие ошибки (MAG)](../../common-errors.md).*

## Логика работы
1. **Приём и валидация:** MAG валидирует тело запроса и наличие сессионных данных, извлекает идентификатор заявки.
2. **Внешний вызов (договор):** запрашивает у Accounting Reader договор по идентификатору заявки; из ответа берёт клиента и партнёра для последующих вызовов.
3. **Внешний вызов (график):** по номеру договора и коду кредитного продукта запрашивает графики платежей и выбирает тот, что относится к нужному договору.
4. **Проверка графика:** если график пуст — возвращает `400`.
5. **Внешний вызов (платёж):** запрашивает данные первого платежа графика, чтобы получить наименование банка и код кредитного продукта.
6. **Формирование ответа:** собирает карточку договора с графиком платежей и возвращает её клиенту.

## Request
```bash
curl -X POST "https://gateway.direct-pay.ru/api/v2/contract/read" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "Meta": {
      "AccountRequestID": "12345"
    }
  }'
```
