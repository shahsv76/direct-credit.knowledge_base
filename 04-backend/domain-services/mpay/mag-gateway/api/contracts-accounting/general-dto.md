# Общие DTO (Contracts & Accounting)

Здесь описаны структуры данных (DTO), которые содержат более одного параметра и используются в двух и более методах группы **Contracts & Accounting API**.

### GeneralData
Сессионные данные клиента, которые MAG получает при проверке токена и передаёт во все методы группы (в коде — контекст `generalData`).

| Название    | Тип                                              | Обязательность | Описание                                                                                            | Пример                                      |
| ----------- | ------------------------------------------------ | -------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `partnerId` | String                                           | Да             | Идентификатор партнёра. Для партнёра `dcpay-mobile` часть логики работает по отдельной ветке        | `dcpay-mobile`                              |
| `clientId`  | String                                           | Да             | Идентификатор клиента в домене партнёра                                                             | `client-123`                                |
| `phone`     | String                                           | Да             | Номер телефона клиента без разделителей                                                             | `79990000000`                               |
| `crmId`     | String                                           | Нет            | Исходный идентификатор клиента до подмены (служебное поле, в ответы не попадает)                    | `crm-456`                                   |
| `data`      | Object                                           | Нет            | Дополнительные атрибуты сессии: `requestId`, `mfoClientId`, `contractClientID`, `contractPartnerID` | `{"requestId": "12345"}`                    |
| `clients`   | Array<[ClientPair](./general-dto.md#clientpair)> | Нет            | Список связанных пар клиент–партнёр для мультиклиентских сценариев                                  | `[{"client_id": "c1", "partner_id": "p1"}]` |

### ClientPair
Связка «клиент — партнёр», используется при мультиклиентском поиске договоров в методах `GET /api/v1/contracts`, `GET /api/v1/contracts/all`, `GET /api/v1/offer/types`, `GET /api/v1/homeScreenContracts`.

| Название     | Тип    | Обязательность | Описание               | Пример         |
| ------------ | ------ | -------------- | ---------------------- | -------------- |
| `client_id`  | String | Да             | Идентификатор клиента  | `client-123`   |
| `partner_id` | String | Да             | Идентификатор партнёра | `dcpay-mobile` |

### AccountingMetaResponse
Стандартный блок метаданных ответов Accounting Service. Возвращается практически во всех методах группы.

| Название | Тип    | Обязательность | Описание                                      | Пример               |
| -------- | ------ | -------------- | --------------------------------------------- | -------------------- |
| `Accept` | String | Да             | Признак успешной обработки: `OK` или `KO`     | `OK`                 |
| `Error`  | String | Нет            | Текст ошибки. Заполняется, если `Accept = KO` | `contract not found` |

### ErrorResponse
Единый формат ошибки MAG для методов группы, где ответ не проксируется из внешнего сервиса (`GET /api/v1/schedule/read`, `GET /api/v1/payment/read`).

| Название  | Тип     | Обязательность | Описание                                           | Пример                    |
| --------- | ------- | -------------- | -------------------------------------------------- | ------------------------- |
| `message` | String  | Да             | Текст ошибки                                       | `response.StatusCode 500` |
| `status`  | Boolean | Да             | Признак успеха операции, при ошибке всегда `false` | `false`                   |

### AccountingContractItem
Элемент списка договоров клиента. Используется в методах: `GET /api/v1/contracts`, `GET /api/v1/contracts/all`, `POST /api/v1/contracts/read`, `POST /api/v2/contracts/read`.

| Название           | Тип      | Обязательность | Описание                       | Пример                 |
| ------------------ | -------- | -------------- | ------------------------------ | ---------------------- |
| `bankContractNum`  | String   | Да             | Номер договора в банке         | `OTP-2026-000123`      |
| `dateConfirm`      | DateTime | Да             | Дата подтверждения договора    | `2026-10-01T12:00:00Z` |
| `bankCode`         | String   | Да             | Код банка                      | `otp`                  |
| `offerTypeCode`    | String   | Да             | Код типа предложения           | `MFO_CASH`             |
| `status`           | String   | Да             | Статус договора                | `AGREEMENT_AUTORIZED`  |
| `clientID`         | String   | Да             | Идентификатор клиента          | `client-123`           |
| `partnerID`        | String   | Да             | Идентификатор партнёра         | `dcpay-mobile`         |
| `accountRequestID` | String   | Да             | Идентификатор заявки на кредит | `12345`                |
