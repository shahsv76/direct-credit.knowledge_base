## Описание
| Тип запроса | Название метода | Описание метода                                                                               | URL                    | Тип  |
| ----------- | --------------- | --------------------------------------------------------------------------------------------- | ---------------------- | ---- |
| GET         | Payment         | Возвращает данные конкретного платежа по графику: банк, реквизиты для оплаты и плановую сумму | `/api/v1/payment/read` | SYNC |

## Входные параметры
### Header
| Название                                           | Тип | Обязательность | Описание           | Пример |
| -------------------------------------------------- | --- | -------------- | ------------------ | ------ |
| 🔗 [Общие заголовки (MAG)](../../common-headers.md) | —   | —              | См. общую страницу | —      |

### Query
| Название    | Тип    | Обязательность | Описание                         | Пример |
| ----------- | ------ | -------------- | -------------------------------- | ------ |
| `paymentID` | String | Да             | Идентификатор платежа из графика | `4567` |

### Body
Тело запроса не используется.

## Выходные параметры
| Название                  | Тип     | Обязательность | Описание                                                          | Пример                 |
| ------------------------- | ------- | -------------- | ----------------------------------------------------------------- | ---------------------- |
| `payment`                 | Object  | Да             | Данные платежа с банковскими реквизитами                          | `{ ... }`              |
| `payment.payID`           | Integer | Да             | Идентификатор платежа                                             | `4567`                 |
| `payment.scheduleID`      | Integer | Да             | Идентификатор графика                                             | `98765`                |
| `payment.planDate`        | String  | Да             | Плановая дата платежа                                             | `2026-11-05`           |
| `payment.planAmountKop`   | Integer | Да             | Плановая сумма в копейках                                         | `1250000`              |
| `payment.bankCode`        | String  | Да             | Код банка                                                         | `otp`                  |
| `payment.bankCreditCode`  | String  | Да             | Код кредитного продукта банка (используется как `appID` договора) | `OTP-CASH`             |
| `payment.bankName`        | String  | Да             | Наименование банка                                                | `ОТП Банк`             |
| `payment.bankINN`         | String  | Нет            | ИНН банка                                                         | `7712040126`           |
| `payment.bankKPP`         | String  | Нет            | КПП банка                                                         | `771201001`            |
| `payment.bankBIK`         | String  | Нет            | БИК банка                                                         | `044525311`            |
| `payment.bankAccountNum`  | String  | Да             | Номер счёта для оплаты                                            | `40817810099910004312` |
| `payment.bankContractNum` | String  | Да             | Номер договора в банке                                            | `OTP-2026-000123`      |

## Коды ответа
| Код ответа | Описание              | Причина                                  |
| ---------- | --------------------- | ---------------------------------------- |
| `200`      | OK                    | Данные платежа получены                  |
| `500`      | INTERNAL_SERVER_ERROR | Ошибка Schedule Reader или чтения ответа |

🔗 *Все общие коды ошибок см. на странице [Общие ошибки (MAG)](../../common-errors.md).*

> ℹ️ Если Schedule Reader вернул иной код ответа (например, `404`), MAG проксирует его клиенту без изменений.

## Логика работы
1. **Приём и валидация:** MAG извлекает идентификатор платежа из query-параметров.
2. **Внешний вызов:** запрашивает у Schedule Reader данные платежа по идентификатору.
3. **Формирование ответа:** возвращает ответ внешнего сервиса без преобразования, сохраняя его код ответа. При ошибке вызова или чтения тела возвращает [`ErrorResponse`](./general-dto.md#errorresponse) с кодом `500`.

## Request
```bash
curl -X GET "https://gateway.direct-pay.ru/api/v1/payment/read?paymentID=4567" \
  -H "Authorization: Bearer <token>"
```
