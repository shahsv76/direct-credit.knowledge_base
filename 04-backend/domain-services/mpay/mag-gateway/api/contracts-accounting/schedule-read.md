| ---------- | --------------------- | ------------------------------------------------------------------- |
| `200`      | OK                    | Графики платежей получены                                           |

## Логика работы
1. **Приём и валидация:** MAG проверяет наличие сессионных данных клиента и формирует запрос с идентификаторами клиента и партнёра.
2. **Выбор сценария:** для партнёра `dcpay-mobile` запускается расширенный сценарий, для остальных — обычный запрос графика.
3. **Внешний вызов (обычный сценарий):** запрашивает графики платежей у Schedule Reader.
4. **Внешний вызов (сценарий `dcpay-mobile`):** получает список связанных клиентов в Client Mapping, параллельно запрашивает графики по каждому клиенту, исключает договоры с кодом банка `dcpay` и объединяет результат.
5. **Формирование ответа:** возвращает массив графиков платежей. При ошибке — объект [`ErrorResponse`](./general-dto.md#errorresponse) с кодом `500`.

## Request
```bash
curl -X GET "https://gateway.direct-pay.ru/api/v1/schedule/read" \
  -H "Authorization: Bearer <token>"
```
