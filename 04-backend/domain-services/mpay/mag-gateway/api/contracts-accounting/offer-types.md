### Query
Клиентские query-параметры не используются. Идентификаторы клиента, партнёра и телефон берутся из сессии ([`GeneralData`](./general-dto.md#generaldata)), а фильтры — из конфигурации сервиса ([`AccountingFilter`](./general-dto.md#accountingfilter)).

| Название    | Источник         | Описание                                                | Пример                                      |
| ----------- | ---------------- | ------------------------------------------------------- | ------------------------------------------- |
| `clientID`  | Сессия (`crmId`) | Идентификатор клиента в CRM                             | `crm-456`                                   |
| `partnerID` | Сессия           | Идентификатор партнёра                                  | `dcpay-mobile`                              |
| `phone`     | Сессия           | Номер телефона клиента                                  | `79990000000`                               |
| `filters`   | Конфигурация     | Фильтры статусов, партнёров, типов предложений и банков | `statusCodes[]=AGREEMENT_AUTORIZED`         |
| `clients`   | Сессия           | Список связанных пар клиент–партнёр                     | `[{"client_id": "c1", "partner_id": "p1"}]` |

### Body
Тело запроса не используется.

## Выходные параметры
Ответ Accounting Service проксируется без преобразования.

| Название                 | Тип    | Обязательность | Описание                                                                                             | Пример             |
| ------------------------ | ------ | -------------- | ---------------------------------------------------------------------------------------------------- | ------------------ |
| Ответ Accounting Service | Object | Да             | Список доступных типов предложений с их атрибутами. Точная структура определяется Accounting Service | `{ "offers": [] }` |

## Коды ответа
| Код ответа | Описание              | Причина                                 |

## Логика работы
1. **Приём и валидация:** MAG проверяет наличие сессионных данных клиента. Если данных нет — возвращает `400`.
2. **Подготовка фильтров:** добавляет фильтры из конфигурации сервиса и список связанных клиентов.
3. **Внешний вызов:** запрашивает у API Accounting доступные типы предложений.
4. **Формирование ответа:** возвращает ответ внешнего сервиса без преобразования, сохраняя его код ответа.

## Request
```bash
curl -X GET "https://gateway.direct-pay.ru/api/v1/offer/types" \
  -H "Authorization: Bearer <token>"
```
