### Body
Тело запроса не используется: клиентские данные MAG берёт из сессии, полученной при проверке токена ([`GeneralData`](./general-dto.md#generaldata)).

| Название    | Тип    | Обязательность | Описание                                                                                                      | Пример         |
| ----------- | ------ | -------------- | ------------------------------------------------------------------------------------------------------------- | -------------- |
| `clientID`  | String | Да             | Идентификатор клиента из сессии. Для партнёра `dcpay-mobile` подменяется номером телефона через Client Reader | `client-123`   |
| `partnerID` | String | Да             | Идентификатор партнёра из сессии или заголовка `X-Mpay-Partner-Id`                                            | `dcpay-mobile` |
| `phone`     | String | Да             | Телефон клиента для поиска связанных идентификаторов                                                          | `79990000000`  |

## Выходные параметры
Ответ Accounting Service проксируется без преобразования.

| Название                                                            | Тип                                                                      | Обязательность | Описание                                         | Пример                                       |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------ | -------------- | ------------------------------------------------ | -------------------------------------------- |
| 🔗 [AccountingMetaResponse](./general-dto.md#accountingmetaresponse) | Object                                                                   | Да             | Метаданные ответа: признак успеха и текст ошибки | `{ "Accept": "OK", "Error": "" }`            |
| `payload.Contracts`                                                 | Array<[AccountingContractItem](./general-dto.md#accountingcontractitem)> | Да             | Список договоров клиента                         | `[{ "bankContractNum": "OTP-2026-000123" }]` |

## Коды ответа
| Код ответа | Описание              | Причина                                                            |
| ---------- | --------------------- | ------------------------------------------------------------------ |
| `200`      | OK                    | Accounting Service вернул результат (код проксируется)             |

## Логика работы
1. **Приём и валидация:** MAG проверяет наличие сессионных данных клиента. Если данных нет — возвращает `400`.
2. **Подмена клиента:** для партнёра `dcpay-mobile` идентификатор клиента заменяется номером телефона через Client Reader.
3. **Поиск связанных клиентов:** запрашивает у Client Reader список идентификаторов по телефону.
4. **Внешний вызов:** передаёт в Accounting Reader идентификатор клиента и найденные связанные идентификаторы.
5. **Формирование ответа:** возвращает ответ Accounting Reader без преобразования. Метод помечен в коде как неработающий — в новых интеграциях не используется.

## Request
```bash
curl -X POST "https://gateway.direct-pay.ru/api/v1/contracts/read" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{}'
```
