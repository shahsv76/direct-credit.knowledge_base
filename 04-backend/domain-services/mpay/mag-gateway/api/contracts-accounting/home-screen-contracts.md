### Query
Клиентские параметры не передаются: MAG берёт данные клиента, партнёра, телефона и связанных клиентов из сессии ([`GeneralData`](./general-dto.md#generaldata)).

### Body
Тело запроса не используется.

## Выходные параметры
| Название                                          | Тип           | Обязательность | Описание                                  | Пример                         |
| ------------------------------------------------- | ------------- | -------------- | ----------------------------------------- | ------------------------------ |
| `accept`                                          | String        | Да             | Признак успешной обработки                | `OK`                           |
| `error`                                           | String        | Нет            | Текст ошибки                              | `""`                           |
| `contracts`                                       | Array<Object> | Да             | Список договоров для главного экрана      | `[]`                           |
| `contracts[].clientID`                            | String        | Да             | Идентификатор клиента                     | `client-123`                   |
| `contracts[].partnerID`                           | String        | Да             | Идентификатор партнёра                    | `dcpay-mobile`                 |
| `contracts[].accountRequestID`                    | String        | Да             | Идентификатор заявки                      | `12345`                        |
| `contracts[].contract`                            | Object        | Да             | Данные договора для главного экрана       | `{ ... }`                      |
| `contracts[].contract.bankCode`                   | String        | Да             | Код банка                                 | `otp`                          |
| `contracts[].contract.offerTypeCode`              | String        | Да             | Код типа предложения                      | `MFO_CASH`                     |
| `contracts[].contract.dateConfirm`                | String        | Да             | Дата подтверждения договора               | `2026-10-01`                   |
| `contracts[].contract.planDate`                   | String        | Нет            | Дата ближайшего платежа                   | `2026-11-05`                   |
| `contracts[].contract.planAmountKop`              | Integer       | Нет            | Сумма ближайшего платежа в копейках       | `1250000`                      |
| `contracts[].contract.paymentStatus`              | String        | Да             | Статус ближайшего платежа                 | `PLANNED`                      |
| `contracts[].contract.bankLogo`                   | String        | Нет            | Ссылка на логотип банка                   | `https://cdn.example/otp.webp` |
| `contracts[].contract.homescreencontracts.status` | String        | Нет            | Статус договора для главного экрана       | `ACTIVE`                       |
| `contracts[].contract.homescreencontracts.days`   | Integer       | Нет            | Количество дней до/после события договора | `12`                           |

## Коды ответа
| Код ответа | Описание              | Причина                                  |
| ---------- | --------------------- | ---------------------------------------- |
| `200`      | OK                    | Список договоров получен                 |
| `400`      | BAD_REQUEST           | В сессии отсутствуют данные клиента      |
| `500`      | INTERNAL_SERVER_ERROR | Ошибка API Accounting или разбора ответа |

🔗 *Все общие коды ошибок см. на странице [Общие ошибки (MAG)](../../common-errors.md).*

> ⚠️ В отличие от остальных методов группы, при ошибке в сессии или на стороне API Accounting MAG отвечает только кодом ответа, без тела ошибки. При ошибке разбора ответа возвращается текстовая строка `failed to decode response`.

## Логика работы
1. **Приём и валидация:** MAG проверяет наличие сессионных данных клиента. Если данных нет — возвращает `400`.
2. **Внешний вызов:** передаёт в API Accounting идентификаторы клиента и партнёра, телефон и связанных клиентов.
3. **Разбор ответа:** приводит ответ внешнего сервиса к формату главного экрана; при ошибке разбора возвращает `500`.
4. **Формирование ответа:** возвращает список договоров с ближайшими платежами и статусами.

## Request
```bash
curl -X GET "https://gateway.direct-pay.ru/api/v1/homeScreenContracts" \
  -H "Authorization: Bearer <token>"
```
