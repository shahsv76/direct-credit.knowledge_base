## Описание
| Тип запроса | Название метода    | Описание метода                                                                                                                                                              | URL                        | Тип  |
| ----------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- | ---- |
| POST        | SetAgreementStatus | Передаёт в Accounting Service новый статус согласия по договору — идентификация договора выполняется по идентификатору заявки в банке или по идентификатору заявки на кредит | `/api/v1/agreement/status` | SYNC |

## Входные параметры
### Header
| Название                                           | Тип | Обязательность | Описание           | Пример |
| -------------------------------------------------- | --- | -------------- | ------------------ | ------ |
| 🔗 [Общие заголовки (MAG)](../../common-headers.md) | —   | —              | См. общую страницу | —      |

### Body
| Название           | Тип    | Обязательность | Описание                                            | Пример             |
| ------------------ | ------ | -------------- | --------------------------------------------------- | ------------------ |
| `bankAppID`        | String | Условно да*    | Идентификатор заявки в банке                        | `APP-98765`        |
| `accountRequestID` | String | Условно да*    | Идентификатор заявки на кредит в Accounting Service | `12345`            |
| `status`           | String | Да             | Новый статус согласия                               | `AGREEMENT_SIGNED` |

\* В DTO задано правило «обязателен, если не передан второй»: должен быть заполнен хотя бы один из идентификаторов — `bankAppID` или `accountRequestID`. Проверку выполняет Accounting Service.

## Выходные параметры
Ответ Accounting Writer проксируется без преобразования.

| Название                                                            | Тип    | Обязательность | Описание                                         | Пример                            |
| ------------------------------------------------------------------- | ------ | -------------- | ------------------------------------------------ | --------------------------------- |
| 🔗 [AccountingMetaResponse](./general-dto.md#accountingmetaresponse) | Object | Да             | Метаданные ответа: признак успеха и текст ошибки | `{ "Accept": "OK", "Error": "" }` |
| `accountRequestID`                                                  | String | Нет            | Идентификатор заявки, по которой обновлён статус | `12345`                           |

## Коды ответа
| Код ответа | Описание              | Причина                                                                       |
| ---------- | --------------------- | ----------------------------------------------------------------------------- |
| `200`      | OK                    | Статус согласия обновлён (код ответа Accounting Writer проксируется)          |
| `500`      | INTERNAL_SERVER_ERROR | Не удалось прочитать тело запроса, ошибка Accounting Writer или чтения ответа |

🔗 *Все общие коды ошибок см. на странице [Общие ошибки (MAG)](../../common-errors.md).*

> ℹ️ Ошибки валидации (например, отсутствие обоих идентификаторов или неизвестный статус) возвращает Accounting Writer — MAG передаёт его код ответа и тело клиенту.

## Логика работы
1. **Приём и валидация:** MAG читает тело запроса и приводит его к структуре с идентификаторами договора и новым статусом. Если тело прочитать не удалось — возвращает `500`.
2. **Внешний вызов:** передаёт данные в Accounting Writer.
3. **Формирование ответа:** возвращает ответ Accounting Writer без преобразования, сохраняя его код ответа.

## Request
```bash
curl -X POST "https://gateway.direct-pay.ru/api/v1/agreement/status" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "bankAppID": "APP-98765",
    "accountRequestID": "12345",
    "status": "AGREEMENT_SIGNED"
  }'
```

## Response
`200 OK`

```json
{
  "meta": {
    "Accept": "OK",
    "Error": ""
  },
  "accountRequestID": "12345"
}
```
