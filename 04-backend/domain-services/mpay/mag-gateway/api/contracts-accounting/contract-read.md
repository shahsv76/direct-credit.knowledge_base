## Коды ответа
| Код ответа | Описание              | Причина                                                                         |
| ---------- | --------------------- | ------------------------------------------------------------------------------- |
| `200`      | OK                    | Карточка договора сформирована                                                  |
| `400`      | BAD_REQUEST           | В сессии отсутствуют данные клиента                                             |
| `500`      | INTERNAL_SERVER_ERROR | Ошибка Accounting Reader, Client Reader или Payment Gate; ошибка разбора ответа |

🔗 *Все общие коды ошибок см. на странице [Общие ошибки (MAG)](../../common-errors.md).*

## Логика работы
1. **Приём и валидация:** MAG проверяет наличие сессионных данных и номер договора в банке. Если данных нет — возвращает `400`.
2. **Внешний вызов (договор):** запрашивает у Accounting Reader карточку договора по номеру договора в банке.
3. **Подмена клиента:** для партнёра `dcpay-mobile` идентификатор клиента заменяется номером телефона через Client Reader.
4. **Внешний вызов (клиент):** по идентификаторам клиента и партнёра запрашивает ФИО, паспортные данные и адрес.
5. **Внешний вызов (платёж):** по коду банка и ежемесячному платежу запрашивает счёт, суммы и комиссию.
6. **Формирование ответа:** объединяет данные трёх сервисов в единую карточку договора. Если счёт клиента в договоре не заполнен, подставляет счёт из данных платежа.

## Request
```bash
curl -X POST "https://gateway.direct-pay.ru/api/v1/contract/read?bankContractNum=OTP-2026-000123" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>"
```
