# POST /api/v3/bestToPay (MAG)

## История изменений

## Описание
| Тип запроса | Название метода | Описание метода                                                                                                                      | URL                 | Тип  |
| ----------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------- | ---- |
| POST        | PaymentURLV3    | Возвращает URL для редиректа пользователя на платёжную форму Best2Pay. Платёж определяется по номеру заявки на кредит (MFO-сценарий) | `/api/v3/bestToPay` | SYNC |

Сценарий для MFO-партнёров: клиент оперирует номером заявки, а не номером договора в банке. Номер договора MAG определяет сам по данным заявки.

| 🔗 [Общие заголовки (MAG)](../../common-headers.md) | —   | —              | См. общую страницу | —      |

### Query
Query-параметры не используются.

### Body
| Название                | Тип     | Обязательность | Описание                                                                                                   | Пример    |
| ----------------------- | ------- | -------------- | ---------------------------------------------------------------------------------------------------------- | --------- |
| `meta`                  | Object  | Да             | Параметры платежа (см. вложенные поля ниже)                                                                | `{ ... }` |
| `meta.accountRequestID` | String  | Да             | Идентификатор заявки на кредит                                                                             | `12345`   |
| `meta.currentAmountKop` | Integer | Нет            | Сумма к оплате в копейках. Если не передана или меньше `1`, MAG подставляет ежемесячный платёж по договору | `1250000` |

Сессионные данные клиента берутся из токена ([`GeneralData`](./general-dto.md#generaldata)).

## Выходные параметры
MAG возвращает ответ платёжного шлюза Best2Pay без изменений.

| Название                                                      | Тип    | Обязательность | Описание                                            | Пример                                                                                 |
| ------------------------------------------------------------- | ------ | -------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 🔗 [Best2PayURLResponse](./general-dto.md#best2payurlresponse) | Object | Да             | Ответ шлюза: метаданные и ссылка на платёжную форму | `{ "meta": { "accept": "OK" }, "payload": { "URL": "https://pay.best2pay.net/..." } }` |

Ключевое поле для интерфейса — `payload.URL`: по этой ссылке пользователь переходит на платёжную форму Best2Pay.

## Коды ответа
| Код ответа | Описание              | Причина                                                                                                           |
| ---------- | --------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `200`      | OK                    | Ссылка на платёжную форму получена                                                                                |
| `400`      | BAD_REQUEST           | Некорректное тело запроса, не передан `meta.accountRequestID` или в сессии нет данных клиента                     |
| `500`      | INTERNAL_SERVER_ERROR | Заявка, договор или клиент не получены, некорректная дата подтверждения договора, ошибка шлюза или разбора ответа |

🔗 *Все общие коды ошибок см. на странице [Общие ошибки (MAG)](../../common-errors.md).*

## Метрика
| Параметр        | Значение                                             |
| --------------- | ---------------------------------------------------- |
| **Имя метрики** | `MetricPaymentRequestMFO`                            |
| **Топик**       | Метрики MAG (`metrics-client`)                       |
| **vendor**      | `mpay-api-gateway (handler.BestToPay.PaymentURLV3()` |

Дополнительно передаются: `clientID`, `partnerID`, `bankContractNum`, `phoneHash` (хеш телефона клиента) и `statusCode` — код ответа шлюза.

## Логика работы
1. **Приём и проверка запроса:** MAG читает номер заявки и сумму, проверяет обязательные поля. При ошибке возвращает `400`.
2. **Проверка сессии:** без сессионных данных клиента дальнейшая обработка невозможна — возвращается `400`.
3. **Внешний вызов (договор):** MAG получает из Accounting Reader договор по номеру заявки на кредит.
4. **Определение суммы:** если сумма не передана, MAG подставляет ежемесячный платёж по договору.
5. **Внешний вызов (клиент):** MAG запрашивает у Client Reader ФИО, адрес и телефон плательщика по данным договора. В качестве признака операции передаётся `requestID` из сессии, а если его нет — признак `/api/v3/bestToPay`.
6. **Уточнение договора:** MAG повторно читает договор, чтобы получить дату его подтверждения — она нужна шлюзу для расчёта первого платежа.
7. **Формирование ссылки:** MAG передаёт шлюзу Best2Pay назначение платежа, сумму, данные плательщика, номер договора, счёт клиента, код банка и дату подтверждения договора.
8. **Ответ:** MAG возвращает пользователю ссылку для редиректа на шлюз Best2Pay и отправляет метрику MFO-сценария.

## Request
```bash
curl -X POST "https://gateway.direct-pay.ru/api/v3/bestToPay" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "meta": {
      "accountRequestID": "12345",
      "currentAmountKop": 1250000
    }
  }'
```

## Response
`200 OK`

```json
{
  "meta": {
    "accept": "OK",
    "error": ""
  },
  "payload": {
    "URL": "https://pay.best2pay.net/webapi/Forward/Forward?payment_id=777777"
  }
}
```
