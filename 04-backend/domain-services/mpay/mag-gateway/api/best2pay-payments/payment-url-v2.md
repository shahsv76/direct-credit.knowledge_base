# POST /api/v2/bestToPay (MAG)

## История изменений

## Описание
| Тип запроса | Название метода | Описание метода                                                                                                                      | URL                 | Тип  |
| ----------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------- | ---- |
| POST        | PaymentURLV2    | Возвращает URL для редиректа пользователя на платёжную форму Best2Pay. Платёж определяется по номеру договора в банке (POS-сценарий) | `/api/v2/bestToPay` | SYNC |

Отличается от v1 тем, что клиент указывает не конкретный платёж из графика, а договор и, при необходимости, сумму. Если сумма не передана, MAG подставляет ежемесячный платёж по договору.

| 🔗 [Общие заголовки (MAG)](../../common-headers.md) | —   | —              | См. общую страницу | —      |

### Query
Query-параметры не используются.

### Body
| Название                | Тип     | Обязательность | Описание                                                                                                   | Пример            |
| ----------------------- | ------- | -------------- | ---------------------------------------------------------------------------------------------------------- | ----------------- |
| `meta`                  | Object  | Да             | Параметры платежа (см. вложенные поля ниже)                                                                | `{ ... }`         |
| `meta.bankContractNum`  | String  | Да             | Номер договора в банке                                                                                     | `OTP-2026-000123` |
| `meta.currentAmountKop` | Integer | Нет            | Сумма к оплате в копейках. Если не передана или меньше `1`, MAG подставляет ежемесячный платёж по договору | `1250000`         |

Сессионные данные клиента берутся из токена ([`GeneralData`](./general-dto.md#generaldata)).

## Выходные параметры
MAG возвращает ответ платёжного шлюза Best2Pay без изменений.

| Название                                                      | Тип    | Обязательность | Описание                                            | Пример                                                                                 |
| ------------------------------------------------------------- | ------ | -------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 🔗 [Best2PayURLResponse](./general-dto.md#best2payurlresponse) | Object | Да             | Ответ шлюза: метаданные и ссылка на платёжную форму | `{ "meta": { "accept": "OK" }, "payload": { "URL": "https://pay.best2pay.net/..." } }` |

Ключевое поле для интерфейса — `payload.URL`: по этой ссылке пользователь переходит на платёжную форму Best2Pay.

## Коды ответа
| Код ответа | Описание              | Причина                                                                                      |
| ---------- | --------------------- | -------------------------------------------------------------------------------------------- |
| `200`      | OK                    | Ссылка на платёжную форму получена                                                           |
| `400`      | BAD_REQUEST           | Некорректное тело запроса, не передан `meta.bankContractNum` или в сессии нет данных клиента |
| `500`      | INTERNAL_SERVER_ERROR | Договор или клиент не получены, ошибка платёжного шлюза или разбора ответа                   |

🔗 *Все общие коды ошибок см. на странице [Общие ошибки (MAG)](../../common-errors.md).*

| Параметр        | Значение                                             |

## Логика работы
1. **Приём и проверка запроса:** MAG читает номер договора и сумму, проверяет обязательные поля. При ошибке возвращает `400`.
2. **Проверка сессии:** без сессионных данных клиента дальнейшая обработка невозможна — возвращается `400`.
3. **Внешний вызов (договор):** MAG получает из Accounting Reader карточку договора по номеру договора в банке.
4. **Нормализация банка:** для ОТП Банка и Сбербанка MAG при необходимости подменяет код банка и очищает номер счёта клиента по правилу из [`enums.md`](./enums.md#нормализация-кода-банка).
5. **Уточнение клиента:** в сессионные данные подставляются идентификаторы клиента и партнёра из договора, после чего MAG запрашивает у Client Reader ФИО, адрес и телефон плательщика.
6. **Подготовка платежа:** MAG повторно читает договор, чтобы получить данные счёта, и определяет сумму: переданную клиентом или ежемесячный платёж по договору.
7. **Формирование ссылки:** MAG передаёт шлюзу Best2Pay назначение платежа, сумму, данные плательщика, номер договора, счёт клиента и код банка. Шлюз возвращает ссылку на платёжную форму.
8. **Ответ:** MAG возвращает пользователю ссылку для редиректа на шлюз Best2Pay и отправляет метрику POS-сценария.

## Request
```bash
curl -X POST "https://gateway.direct-pay.ru/api/v2/bestToPay" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "meta": {
      "bankContractNum": "OTP-2026-000123",
      "currentAmountKop": 1250000
    }
  }'
```

## Response
`200 OK`

```json
{
  "meta": {
    "accept": "OK",
    "error": ""
  },
  "payload": {
    "URL": "https://pay.best2pay.net/webapi/Forward/Forward?payment_id=654321"
  }
}
```
