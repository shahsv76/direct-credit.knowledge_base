## Описание
| Тип запроса | Название метода | Описание метода                                                                                                      | URL                   | Тип  |
| ----------- | --------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------- | ---- |
| GET         | Recalculate     | Пересчитывает параметры платежа по заявке при изменении суммы: сумму погашения, комиссию и итоговую сумму к списанию | `/api/v1/recalculate` | SYNC |

Метод используется, когда клиент вводит свою сумму платежа и интерфейсу нужно показать пересчитанные значения до подтверждения оплаты.

## Входные параметры
### Header
| Название                                           | Тип | Обязательность | Описание           | Пример |
| -------------------------------------------------- | --- | -------------- | ------------------ | ------ |
| 🔗 [Общие заголовки (MAG)](../../common-headers.md) | —   | —              | См. общую страницу | —      |

### Query
| Название           | Тип    | Обязательность | Описание                                                                                                                                    | Пример    |
| ------------------ | ------ | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| `accountRequestID` | String | Да             | Идентификатор заявки на кредит                                                                                                              | `12345`   |
| `currentAmountKop` | String | Нет            | Новая сумма платежа в копейках. Пустое значение или `nan` трактуются как `0`. Отрицательное или нечисловое значение приводит к ошибке `400` | `1250000` |

### Body
Тело запроса не используется. Данные клиента берутся из сессии ([`GeneralData`](./general-dto.md#generaldata)): в расчёт передаётся исходный идентификатор клиента и идентификатор партнёра.

## Выходные параметры
MAG возвращает ответ сервиса проведения платежей без изменений — и код ответа, и тело.

| Название    | Тип                             | Обязательность | Описание                                                                                                                                   | Пример                   |
| ----------- | ------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------ |
| Тело ответа | Object (ответ внешнего сервиса) | Да             | Пересчитанные параметры платежа: сумма погашения, комиссия и итоговая сумма. Структура определяется контрактом сервиса проведения платежей | `{ "payload": { ... } }` |

## Коды ответа
| Код ответа | Описание              | Причина                                                                              |
| ---------- | --------------------- | ------------------------------------------------------------------------------------ |
| `200`      | OK                    | Пересчёт выполнен                                                                    |
| `400`      | BAD_REQUEST           | В сессии нет данных клиента, `currentAmountKop` отрицательный или не является числом |
| `500`      | INTERNAL_SERVER_ERROR | Ошибка пересчёта на стороне сервиса проведения платежей или чтения ответа            |

🔗 *Все общие коды ошибок см. на странице [Общие ошибки (MAG)](../../common-errors.md).*

## Логика работы
1. **Проверка сессии:** если данных клиента нет, возвращается `400`.
2. **Разбор суммы:** MAG нормализует переданную сумму: пустое значение и `nan` превращаются в `0`, отрицательное или нечисловое значение — ошибка `400`.
3. **Внешний вызов:** MAG передаёт сервису проведения платежей номер заявки, сумму и идентификаторы клиента и партнёра.
4. **Ответ:** MAG возвращает клиенту пересчитанные значения и код ответа сервиса.

## Request
```bash
curl -X GET "https://gateway.direct-pay.ru/api/v1/recalculate?accountRequestID=12345&currentAmountKop=1250000" \
  -H "Authorization: Bearer <token>"
```

## Response
`200 OK`

```json
{
  "payload": {
    "currentAmountKop": 1250000,
    "feeAmountKop": 37000,
    "totalAmountKop": 1287000
  }
}
```

> 💡 Точный набор полей ответа определяет сервис проведения платежей: MAG передаёт его тело клиенту без изменений.
