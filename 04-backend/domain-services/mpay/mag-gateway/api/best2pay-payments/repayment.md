## Описание
| Тип запроса | Название метода | Описание метода                                                                                                                                                 | URL                          | Тип  |
| ----------- | --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | ---- |
| POST        | Repayment       | Рассчитывает параметры погашения и возвращает URL для редиректа пользователя на платёжную форму Best2Pay вместе с суммой погашения, комиссией и итоговой суммой | `/api/v1/contract/repayment` | SYNC |

Метод используется перед оплатой, когда интерфейсу нужно показать клиенту, из чего складывается сумма: сколько идёт в погашение договора, какая берётся комиссия и сколько всего спишется.

### Query
Query-параметры не используются.

### Body
| Название                | Тип     | Обязательность | Описание                                            | Пример    |
| ----------------------- | ------- | -------------- | --------------------------------------------------- | --------- |
| `meta`                  | Object  | Да             | Параметры погашения (см. вложенные поля ниже)       | `{ ... }` |
| `meta.bankCode`         | String  | Да             | Код банка, по которому рассчитывается погашение     | `otp`     |
| `meta.currentAmountKop` | Integer | Да             | Сумма погашения в копейках. Должна быть больше нуля | `1250000` |

Сессионные данные клиента берутся из токена ([`GeneralData`](./general-dto.md#generaldata)).

## Выходные параметры
MAG возвращает ответ платёжного шлюза Best2Pay без изменений.

| Название                   | Тип     | Обязательность | Описание                                                       | Пример                                |
| -------------------------- | ------- | -------------- | -------------------------------------------------------------- | ------------------------------------- |
| `meta`                     | Object  | Да             | Метаданные ответа шлюза (см. вложенные поля ниже)              | `{ ... }`                             |
| `meta.accept`              | String  | Да             | Признак успешной обработки: `OK` или `KO`                      | `OK`                                  |
| `meta.error`               | String  | Нет            | Текст ошибки шлюза. Заполняется, если `accept = KO`            | `bank is not available`               |
| `payload`                  | Object  | Да             | Суммы и ссылка на оплату (см. вложенные поля ниже)             | `{ ... }`                             |
| `payload.repaymentUrl`     | String  | Да             | URL для редиректа пользователя на платёжную форму Best2Pay     | `https://pay.best2pay.net/webapi/...` |
| `payload.currentAmountKop` | Integer | Да             | Сумма, которая идёт в погашение договора, в копейках           | `1250000`                             |
| `payload.feeAmountKop`     | Integer | Да             | Комиссия за платёж в копейках                                  | `37000`                               |
| `payload.totalAmountKop`   | Integer | Да             | Итоговая сумма к списанию: погашение плюс комиссия, в копейках | `1287000`                             |

## Коды ответа
| Код ответа | Описание              | Причина                                                                                          |
| ---------- | --------------------- | ------------------------------------------------------------------------------------------------ |
| `200`      | OK                    | Параметры погашения рассчитаны, ссылка на оплату получена                                        |
| `400`      | BAD_REQUEST           | Некорректное тело запроса, `currentAmountKop` меньше или равен нулю, в сессии нет данных клиента |
| `500`      | INTERNAL_SERVER_ERROR | Ошибка расчёта на стороне платёжного шлюза или разбора ответа                                    |

🔗 *Все общие коды ошибок см. на странице [Общие ошибки (MAG)](../../common-errors.md).*

## Логика работы
1. **Приём и проверка запроса:** MAG читает тело запроса и проверяет сумму погашения — она должна быть больше нуля. Иначе возвращается `400`.
2. **Проверка сессии:** если данных клиента нет, возвращается `400`.
3. **Расчёт погашения:** MAG передаёт платёжному шлюзу Best2Pay код банка и сумму погашения.
4. **Формирование ответа:** шлюз рассчитывает комиссию, итоговую сумму и формирует ссылку на платёжную форму. MAG возвращает этот ответ без изменений.
5. **Редирект:** пользователь переходит по `payload.repaymentUrl` на платёжную форму Best2Pay и завершает оплату на стороне шлюза.

## Request
```bash
curl -X POST "https://gateway.direct-pay.ru/api/v1/contract/repayment" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "meta": {
      "bankCode": "otp",
      "currentAmountKop": 1250000
    }
  }'
```

## Response
`200 OK`

```json
{
  "meta": {
    "accept": "OK",
    "error": ""
  },
  "payload": {
    "repaymentUrl": "https://pay.best2pay.net/webapi/Forward/Forward?payment_id=888888",
    "currentAmountKop": 1250000,
    "feeAmountKop": 37000,
    "totalAmountKop": 1287000
  }
}
```
