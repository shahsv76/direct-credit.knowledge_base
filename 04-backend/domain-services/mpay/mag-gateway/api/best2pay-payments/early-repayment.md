# POST /api/v1/contract/early/repayment (MAG)

## История изменений
| Дата       | Задача                                                 | Автор                                                                            | Изменение                             |

## Описание
| Тип запроса | Название метода                 | Описание метода                                                                                   | URL                                | Тип  |
| ----------- | ------------------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------- | ---- |
| POST        | CreateApplicationEarlyRepayment | Создаёт заявку на досрочное погашение договора: полное или частичное, на выбранную клиентом сумму | `/api/v1/contract/early/repayment` | SYNC |

Метод оформляет намерение клиента погасить договор досрочно. После создания заявки клиент оплачивает договор одним из способов оплаты — через ссылку на платёжную форму Best2Pay или через оплату по карте.

| `accountRequestID`  | String  | Да             | Идентификатор заявки на кредит                                                                     | `12345`           |

| `repaymentTypeCode` | String  | Да             | Тип досрочного погашения: полное или частичное (см. [`enums.md`](./enums.md#коды-типов-погашения)) | `EARLY_FULL`      |

## Коды ответа
| Код ответа | Описание              | Причина                                                                                |
| ---------- | --------------------- | -------------------------------------------------------------------------------------- |
| `200`      | OK                    | Заявка создана, возвращены её данные                                                   |
| `400`      | BAD_REQUEST           | Некорректное тело запроса, не заполнены обязательные поля, в сессии нет данных клиента |
| `500`      | INTERNAL_SERVER_ERROR | Не удалось создать заявку в Accounting или подготовить ответ                           |

При ошибке создания заявки MAG возвращает `500` и тело в формате ответа метода: `meta.error = KO`, `payload.errorCode = 500`.

🔗 *Все общие коды ошибок см. на странице [Общие ошибки (MAG)](../../common-errors.md).*

## Логика работы
1. **Приём и проверка запроса:** MAG читает тело запроса. Если тело не читается или не разбирается, возвращается `400`.
2. **Проверка сессии:** если данных клиента нет, возвращается `400`.
3. **Формирование заявки:** MAG дополняет запрос служебными данными: идентификаторами клиента и партнёра из сессии, собственным идентификатором запроса, признаком потребителя `mf-gateway` и источником `mf`.
4. **Создание заявки:** MAG передаёт заявку в Accounting.
5. **Обработка ошибки:** если заявку создать не удалось, MAG возвращает `500` с признаком ошибки `KO` и кодом ошибки в теле ответа.
6. **Ответ:** при успехе MAG возвращает `200` и данные созданной заявки: статус, сумму, дату погашения и подпись типа погашения.

## Request
```bash
curl -X POST "https://gateway.direct-pay.ru/api/v1/contract/early/repayment" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "accountRequestID": "12345",
    "bankContractNum": "OTP-2026-000123",
    "repaymentTypeCode": "EARLY_FULL",
    "amountKop": 13500000
  }'
```
