# Общие DTO (Best2Pay & Payments)

Здесь описаны структуры данных (DTO), которые используются в двух и более методах группы **Best2Pay & Payments API**. Структуры, применяемые только в одном методе, описаны прямо на странице этого метода.

### GeneralData

Сессионные данные клиента, которые MAG получает при проверке токена и использует во всех методах группы (в коде — контекст `generalData`).

| Название                 | Тип                                              | Обязательность | Описание                                                                                              | Пример                                      |
| ------------------------ | ------------------------------------------------ | -------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `partnerId`              | String                                           | Да             | Идентификатор партнёра                                                                                | `dcpay-mobile`                              |
| `clientId`               | String                                           | Да             | Идентификатор клиента в домене партнёра                                                               | `client-123`                                |
| `phone`                  | String                                           | Да             | Номер телефона клиента без разделителей. Используется для запроса данных клиента и для хеша в метрике | `79990000000`                               |
| `crmId`                  | String                                           | Нет            | Исходный идентификатор клиента до подмены (служебное поле, в ответы не попадает)                      | `crm-456`                                   |
| `data`                   | Object                                           | Нет            | Дополнительные атрибуты сессии (см. вложенные поля ниже)                                              | `{"requestId": "12345"}`                    |
| `data.requestId`         | String                                           | Нет            | Идентификатор запроса, инициировавшего обращение. Используется как признак операции в методе v3       | `12345`                                     |
| `data.contractClientID`  | String                                           | Нет            | Идентификатор клиента из договора. Применяется в методе v2 вместо идентификатора из сессии            | `client-123`                                |
| `data.contractPartnerID` | String                                           | Нет            | Идентификатор партнёра из договора. Применяется в методе v2 вместо идентификатора из сессии           | `dcpay-mobile`                              |
| `data.mfoClientId`       | String                                           | Нет            | Идентификатор клиента в MFO-контуре                                                                   | `mfo-789`                                   |
| `clients`                | Array<[ClientPair](./general-dto.md#clientpair)> | Нет            | Список связанных пар клиент–партнёр для мультиклиентских сценариев                                    | `[{"client_id": "c1", "partner_id": "p1"}]` |

### ClientPair

Связка «клиент — партнёр», передаётся в составе сессионных данных.

| Название     | Тип    | Обязательность | Описание               | Пример         |
| ------------ | ------ | -------------- | ---------------------- | -------------- |
| `client_id`  | String | Да             | Идентификатор клиента  | `client-123`   |
| `partner_id` | String | Да             | Идентификатор партнёра | `dcpay-mobile` |

### ClientResponse

Данные клиента из Client Reader. Нужны для формирования данных плательщика при получении ссылки на оплату, поэтому используются в методах [`GET /api/v1/bestToPay`](./payment-url-v1.md), [`POST /api/v2/bestToPay`](./payment-url-v2.md) и [`POST /api/v3/bestToPay`](./payment-url-v3.md).

| Название        | Тип     | Обязательность | Описание                         | Пример                           |
| --------------- | ------- | -------------- | -------------------------------- | -------------------------------- |
| `ID`            | Integer | Да             | Внутренний идентификатор клиента | `100500`                         |
| `phone`         | String  | Да             | Номер телефона клиента           | `9990000000`                     |
| `lastName`      | String  | Да             | Фамилия                          | `Иванов`                         |
| `firstName`     | String  | Да             | Имя                              | `Иван`                           |
| `secondName`    | String  | Да             | Отчество                         | `Иванович`                       |
| `addressString` | String  | Да             | Адрес регистрации одной строкой  | `г. Москва, ул. Примерная, д. 1` |

### AccountingContractsResponse

Ответ Accounting Reader с данными договора. Используется в методах [`POST /api/v2/bestToPay`](./payment-url-v2.md) и [`POST /api/v3/bestToPay`](./payment-url-v3.md).

| Название           | Тип                                                         | Обязательность | Описание                                      | Пример                    |
| ------------------ | ----------------------------------------------------------- | -------------- | --------------------------------------------- | ------------------------- |
| `meta`             | Object                                                      | Да             | Метаданные ответа (см. вложенные поля ниже)   | `{ "Accept": "OK" }`      |
| `meta.Accept`      | String                                                      | Да             | Признак успешной обработки: `OK` или `KO`     | `OK`                      |
| `meta.Error`       | String                                                      | Нет            | Текст ошибки. Заполняется, если `Accept = KO` | `contract not found`      |
| `payload`          | Object                                                      | Да             | Данные договора (см. вложенные поля ниже)     | `{ "Contract": { ... } }` |
| `payload.Contract` | 🔗 [AccountingContract](./general-dto.md#accountingcontract) | Да             | Договор клиента                               | `{ ... }`                 |

### AccountingContract

Договор клиента в Accounting Reader.

| Название            | Тип     | Обязательность | Описание                                           | Пример                 |
| ------------------- | ------- | -------------- | -------------------------------------------------- | ---------------------- |
| `bankCode`          | String  | Да             | Код банка                                          | `otp`                  |
| `appID`             | String  | Да             | Идентификатор заявки в банке                       | `APP-000123`           |
| `clientAccountNum`  | String  | Нет            | Номер счёта клиента. Может быть пустым             | `40817810099910004312` |
| `bankContractNum`   | String  | Да             | Номер договора в банке                             | `OTP-2026-000123`      |
| `dateConfirm`       | String  | Да             | Дата подтверждения договора в формате `ГГГГ-ММ-ДД` | `2026-10-01`           |
| `termMonth`         | Integer | Да             | Срок договора в месяцах                            | `24`                   |
| `contractAmountKop` | Integer | Да             | Сумма договора в копейках                          | `15000000`             |
| `monthlyAmountKop`  | Integer | Да             | Ежемесячный платёж в копейках                      | `1250000`              |
| `clientID`          | String  | Да             | Идентификатор клиента                              | `client-123`           |
| `partnerID`         | String  | Да             | Идентификатор партнёра                             | `dcpay-mobile`         |
| `createdBy`         | String  | Нет            | Система, создавшая договор                         | `mpay_api_gateway`     |
| `createdByOp`       | String  | Нет            | Операция-инициатор создания договора               | `request: 12345`       |

### Best2PayURLResponse

Ответ платёжного шлюза Best2Pay со ссылкой на платёжную форму. Используется в методах [`GET /api/v1/bestToPay`](./payment-url-v1.md), [`POST /api/v2/bestToPay`](./payment-url-v2.md) и [`POST /api/v3/bestToPay`](./payment-url-v3.md).

| Название      | Тип    | Обязательность | Описание                                                      | Пример                                |
| ------------- | ------ | -------------- | ------------------------------------------------------------- | ------------------------------------- |
| `meta`        | Object | Да             | Метаданные ответа шлюза (см. вложенные поля ниже)             | `{ "accept": "OK" }`                  |
| `meta.accept` | String | Да             | Признак успешной обработки: `OK` или `KO`                     | `OK`                                  |
| `meta.error`  | String | Нет            | Текст ошибки шлюза. Заполняется, если `accept = KO`           | `bank is not available`               |
| `payload`     | Object | Да             | Данные платежа (см. вложенные поля ниже)                      | `{ "URL": "https://..." }`            |
| `payload.URL` | String | Да             | Ссылка для редиректа пользователя на платёжную форму Best2Pay | `https://pay.best2pay.net/webapi/...` |

> ⚠️ MAG возвращает тело ответа платёжного шлюза без изменений. В таблице приведены поля, на которые опирается партнёрский интерфейс; остальные поля шлюза проксируются как есть.

### MetaResponse

Единый формат ошибки методов группы, когда MAG отвечает сам, а не проксирует ответ внешнего сервиса.

| Название      | Тип    | Обязательность | Описание                                            | Пример               |
| ------------- | ------ | -------------- | --------------------------------------------------- | -------------------- |
| `meta`        | Object | Да             | Метаданные ошибки (см. вложенные поля ниже)         | `{ "Accept": "KO" }` |
| `meta.Accept` | String | Да             | Признак успеха, при ошибке всегда `KO`              | `KO`                 |
| `meta.Error`  | String | Да             | Текст ошибки                                        | `generalData is nil` |
| `payload`     | Object | Нет            | Дополнительные данные, при ошибке как правило пусто | —                    |

### ErrorResponse

Формат ошибки, который MAG использует в методе [`GET /api/v1/bestToPay`](./payment-url-v1.md).

| Название  | Тип     | Обязательность | Описание                                           | Пример             |
| --------- | ------- | -------------- | -------------------------------------------------- | ------------------ |
| `message` | String  | Да             | Текст ошибки                                       | `client not found` |
| `status`  | Boolean | Да             | Признак успеха операции, при ошибке всегда `false` | `false`            |
