## Описание
| Тип запроса | Название метода | Описание метода                                                                                                                            | URL                      | Тип  |
| ----------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------ | ---- |
| POST        | PayB2P          | Проводит оплату по договору через B2P — новой картой или сохранённой картой клиента, с возможностью сохранить карту для следующих платежей | `/api/v1/payment/payb2p` | SYNC |

В отличие от методов `bestToPay`, этот метод не возвращает ссылку на платёжную форму: оплата проводится сразу, а MAG возвращает результат проведения платежа.

| 🔗 [Общие заголовки (MAG)](../../common-headers.md) | —   | —              | См. общую страницу | —      |

### Query
Query-параметры не используются.

### Body
| Название            | Тип     | Обязательность | Описание                                                                                     | Пример     |
| ------------------- | ------- | -------------- | -------------------------------------------------------------------------------------------- | ---------- |
| `accountRequestID`  | String  | Да             | Идентификатор заявки на кредит                                                               | `12345`    |
| `currentAmountKop`  | Integer | Да             | Сумма платежа в копейках                                                                     | `1250000`  |
| `saveCard`          | Boolean | Нет            | Признак «сохранить карту для следующих платежей»                                             | `true`     |
| `repaymentTypeCode` | String  | Нет            | Тип погашения (см. [`enums.md`](./enums.md#коды-типов-погашения))                            | `EARLY`    |
| `cardHash`          | String  | Нет            | Признак сохранённой карты. Если передан, оплата проходит по сохранённой карте, а не по новой | `a1b2c3d4` |

> ⚠️ Поля `clientID` и `partnerID` в теле запроса MAG игнорирует: идентификаторы клиента и партнёра всегда берутся из сессии ([`GeneralData`](./general-dto.md#generaldata)).

## Выходные параметры
MAG возвращает ответ сервиса проведения платежей без изменений — и код ответа, и тело.

| Название    | Тип                             | Обязательность | Описание                                                                                                                             | Пример                                    |
| ----------- | ------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------- |
| Тело ответа | Object (ответ внешнего сервиса) | Да             | Результат проведения платежа: метаданные операции и её идентификаторы. Структура определяется контрактом сервиса проведения платежей | `{ "meta": { ... }, "payload": { ... } }` |

## Коды ответа
| Код ответа | Описание              | Причина                                                            |
| ---------- | --------------------- | ------------------------------------------------------------------ |
| `200`      | OK                    | Платёж проведён, ответ сервиса проведения платежей передан клиенту |
| `400`      | BAD_REQUEST           | Некорректное тело запроса, в сессии нет данных клиента             |
| `500`      | INTERNAL_SERVER_ERROR | Ошибка проведения платежа или чтения ответа                        |

🔗 *Все общие коды ошибок см. на странице [Общие ошибки (MAG)](../../common-errors.md).*

## Метрика
| Параметр        | Значение                                         |
| --------------- | ------------------------------------------------ |
| **Имя метрики** | `MetricGetPayB2P`                                |
| **Топик**       | Метрики MAG (`metrics-client`)                   |
| **vendor**      | `mpay-api-geteway handler.Payment.PayB2P.result` |

Дополнительно передаются признаки `saveCard` (`0`/`1`) и `cards` (`1`, если оплата идёт по сохранённой карте). Ошибки на каждом шаге обработки также отправляются отдельной метрикой с указанием этапа.

## Логика работы
1. **Проверка сессии:** если данных клиента нет, возвращается `400`.
2. **Приём и проверка запроса:** MAG читает тело запроса и проверяет его структуру. При ошибке возвращается `400` и отправляется метрика с этапом ошибки.
3. **Подстановка клиента:** идентификаторы клиента и партнёра из сессии записываются в данные платежа вместо переданных в теле.
4. **Выбор сценария:** если передан признак сохранённой карты, платёж проводится по сохранённой карте, иначе — по новой карте.
5. **Проведение платежа:** MAG передаёт сервису проведения платежей номер заявки, сумму, тип погашения, признак сохранения карты и признак сохранённой карты.
6. **Ответ:** MAG возвращает клиенту результат проведения платежа и отправляет метрику с кодом ответа и признаками сценария.

## Request
```bash
curl -X POST "https://gateway.direct-pay.ru/api/v1/payment/payb2p" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "accountRequestID": "12345",
    "currentAmountKop": 1250000,
    "saveCard": true,
    "repaymentTypeCode": "EARLY",
    "cardHash": "a1b2c3d4"
  }'
```

## Response
`200 OK`

```json
{
  "meta": {
    "accept": "OK",
    "error": ""
  },
  "payload": {
    "paymentID": "987654321",
    "status": "APPROVED"
  }
}
```

> 💡 Точный набор полей ответа определяет сервис проведения платежей: MAG передаёт его тело клиенту без изменений.
