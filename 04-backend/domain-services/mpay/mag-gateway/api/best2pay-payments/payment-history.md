# GET /api/v1/payment/history (MAG)

## История изменений

## Описание
| Тип запроса | Название метода | Описание метода                                                                                                                        | URL                       | Тип  |
| ----------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- | ---- |
| GET         | GetHistory      | Возвращает список операций клиента, отсортированный по дате от новых к старым, с подписями статусов и датами в удобном для показа виде | `/api/v1/payment/history` | SYNC |

Метод используется для экрана истории платежей: интерфейс запрашивает страницу операций и показывает, была ли операция принята, отклонена или ещё обрабатывается.

## Входные параметры
### Header
| Название                                           | Тип | Обязательность | Описание           | Пример |
| -------------------------------------------------- | --- | -------------- | ------------------ | ------ |
| 🔗 [Общие заголовки (MAG)](../../common-headers.md) | —   | —              | См. общую страницу | —      |

### Query
| Название | Тип     | Обязательность | Описание                                                                | Пример |
| -------- | ------- | -------------- | ----------------------------------------------------------------------- | ------ |
| `limit`  | Integer | Да             | Максимальное количество операций на странице. Должно быть не меньше `1` | `20`   |
| `offset` | Integer | Да             | Смещение от начала списка. Должно быть не меньше `0`                    | `0`    |

### Body
Тело запроса не используется. Идентификаторы клиента и партнёра берутся из сессии ([`GeneralData`](./general-dto.md#generaldata)).

## Коды ответа
| Код ответа | Описание              | Причина                                                                                               |
| ---------- | --------------------- | ----------------------------------------------------------------------------------------------------- |
| `200`      | OK                    | Страница операций сформирована                                                                        |
| `400`      | BAD_REQUEST           | В сессии нет данных клиента, `limit` не передан или меньше `1`, `offset` не передан или отрицательный |
| `500`      | INTERNAL_SERVER_ERROR | Сервис проведения платежей вернул ошибку или не удалось подготовить ответ                             |

🔗 *Все общие коды ошибок см. на странице [Общие ошибки (MAG)](../../common-errors.md).*

## Логика работы
1. **Проверка сессии:** если данных клиента нет, возвращается `400`.
2. **Проверка пагинации:** MAG проверяет `limit` и `offset`. Некорректные значения приводят к ошибке `400`.
3. **Запрос операций:** MAG запрашивает у сервиса проведения платежей на одну операцию больше, чем просил клиент, — чтобы понять, есть ли следующая страница.
4. **Определение продолжения:** если операций пришло больше, чем `limit`, MAG выставляет признак `hasMoreData` и обрезает список до запрошенного размера.
5. **Оформление:** для каждой операции MAG переводит код состояния в понятную подпись и форматирует дату на русском языке, а сумму оставляет в копейках.
6. **Ответ:** MAG возвращает страницу операций и признак наличия следующей страницы.

## Request
```bash
curl -X GET "https://gateway.direct-pay.ru/api/v1/payment/history?limit=20&offset=0" \
  -H "Authorization: Bearer <token>"
```
