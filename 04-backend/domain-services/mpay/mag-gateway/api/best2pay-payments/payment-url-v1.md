## Описание
| Тип запроса | Название метода | Описание метода                                                                                                                 | URL                 | Тип  |
| ----------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------- | ---- |
| GET         | PaymentURL      | Возвращает URL для редиректа пользователя на платёжную форму Best2Pay. Платёж определяется по идентификатору платежа из графика | `/api/v1/bestToPay` | SYNC |

Метод — самый простой сценарий оплаты: партнёрский интерфейс уже знает конкретный платёж из графика и передаёт его идентификатор.

## Входные параметры
### Header
| Название                                           | Тип | Обязательность | Описание           | Пример |
| -------------------------------------------------- | --- | -------------- | ------------------ | ------ |
| 🔗 [Общие заголовки (MAG)](../../common-headers.md) | —   | —              | См. общую страницу | —      |

### Query
| Название    | Тип    | Обязательность | Описание                        | Пример   |
| ----------- | ------ | -------------- | ------------------------------- | -------- |
| `paymentID` | String | Да             | Идентификатор платежа в графике | `123456` |

### Body
Тело запроса не используется. Данные клиента берутся из сессии ([`GeneralData`](./general-dto.md#generaldata)).

## Выходные параметры
MAG возвращает ответ платёжного шлюза Best2Pay без изменений.

| Название                                                      | Тип    | Обязательность | Описание                                            | Пример                                                                                 |
| ------------------------------------------------------------- | ------ | -------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 🔗 [Best2PayURLResponse](./general-dto.md#best2payurlresponse) | Object | Да             | Ответ шлюза: метаданные и ссылка на платёжную форму | `{ "meta": { "accept": "OK" }, "payload": { "URL": "https://pay.best2pay.net/..." } }` |

Ключевое поле для интерфейса — `payload.URL`: по этой ссылке пользователь переходит на платёжную форму Best2Pay.

## Коды ответа
| Код ответа | Описание              | Причина                                                                                                             |
| ---------- | --------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `200`      | OK                    | Ссылка на платёжную форму получена (или шлюз вернул свой код успеха)                                                |
| `400`      | BAD_REQUEST           | В сессии нет данных клиента. Обработка прекращается, тело ответа остаётся пустым                                    |
| `500`      | INTERNAL_SERVER_ERROR | Платёж не найден, договор или клиент не получены, не заполнены обязательные данные, ошибка шлюза или разбора ответа |

🔗 *Все общие коды ошибок см. на странице [Общие ошибки (MAG)](../../common-errors.md).*

## Метрика
| Параметр        | Значение                                           |
| --------------- | -------------------------------------------------- |
| **Имя метрики** | `MetricPaymentRequestMR`                           |
| **Топик**       | Метрики MAG (`metrics-client`)                     |
| **vendor**      | `mpay-api-gateway (handler.BestToPay.PaymentURL()` |

Дополнительно передаются: `clientID`, `partnerID`, `paymentID`, `phoneHash` (хеш телефона клиента) и `statusCode` — код ответа шлюза.

## Логика работы
1. **Приём запроса:** MAG читает идентификатор платежа `paymentID` и сессионные данные клиента.
2. **Проверка сессии:** если данных клиента нет, обработка прекращается без формирования тела ответа.
3. **Внешний вызов (платёж):** MAG запрашивает у Payment Reader платёж по его идентификатору: дату, сумму, банк, реквизиты и номер договора.
4. **Проверка платежа:** обязательные поля платежа должны быть заполнены, иначе возвращается `500`.
5. **Внешний вызов (договор):** по номеру договора в банке MAG получает краткую карточку договора, чтобы определить клиента и партнёра.
6. **Внешний вызов (клиент):** по идентификаторам клиента и партнёра MAG получает ФИО, адрес и телефон плательщика.
7. **Формирование ссылки:** MAG передаёт шлюзу Best2Pay назначение платежа, сумму в копейках, данные плательщика и реквизиты получателя и получает ссылку на платёжную форму.
8. **Ответ:** MAG возвращает пользователю ссылку для редиректа на шлюз Best2Pay и отправляет метрику с кодом ответа шлюза.

## Request
```bash
curl -X GET "https://gateway.direct-pay.ru/api/v1/bestToPay?paymentID=123456" \
  -H "Authorization: Bearer <token>"
```

## Response
`200 OK`

```json
{
  "meta": {
    "accept": "OK",
    "error": ""
  },
  "payload": {
    "URL": "https://pay.best2pay.net/webapi/Forward/Forward?payment_id=123456"
  }
}
```
