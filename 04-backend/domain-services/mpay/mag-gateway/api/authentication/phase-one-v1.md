# POST /api/v1/authentication/phase_one (MAG)

| Тип запроса | Название метода | Описание метода                                                                                                    | URL                                | Тип  |

| POST        | PhaseOneShort   | Упрощённая первая фаза авторизации (v1): проверяет токен, получает список соглашений и отправляет OTP-код клиенту. | `/api/v1/authentication/phase_one` | SYNC |

## Коды ответа
| Код ответа | Описание              | Причина                                                       |
| ---------- | --------------------- | ------------------------------------------------------------- |
| `201`      | CREATED               | Токен проверен, OTP отправлен, соглашения получены            |
| `400`      | BAD_REQUEST           | Некорректное тело запроса                                     |
| `500`      | INTERNAL_SERVER_ERROR | Ошибка проверки токена, получения соглашений или отправки OTP |

## Логика работы
1. **Приём и валидация:** MAG принимает запрос и валидирует поле `token`.
2. **Внешний вызов:** Вызывает Authentication Service (`/api/v1/check_token`) для проверки токена и получения `clientID`, `phone`, `partnerID`.
3. **Получение соглашений:** Запрашивает список документов в Offer Service (`/v1/getCommonDocsInfoByDocTypes`), сортирует соглашения по `DOC_TYPES_LIST` (см. [ENUM](./enums.md#типы-документов-сопд)).
4. **Отправка OTP:** Вызывает OTP Service (`/otp/v2/send`) для отправки кода клиенту.
5. **Формирование ответа:** Собирает `xOTPToken` и список соглашений и возвращает клиенту с кодом `201`.

## Request
```bash
curl -X POST "https://gateway.direct-pay.ru/api/v1/authentication/phase_one" \
  -H "Content-Type: application/json" \
  -d '{ "token": "0abfb32e303d35bc68cb3e70018c6551" }'
```
