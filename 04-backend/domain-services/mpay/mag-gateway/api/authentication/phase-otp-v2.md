# POST /api/v2/authentication/phase_otp (MAG)

## Описание
| Тип запроса | Название метода | Описание метода                                                                                                         | URL                                | Тип  |
| ----------- | --------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------- | ---- |
| POST        | PhaseOTP        | Вторая фаза авторизации (v2): подтверждает OTP-код, регистрирует клиента и выдаёт новый PIN-токен для установки пароля. | `/api/v2/authentication/phase_otp` | SYNC |

| -------------------------------------------------- | --- | -------------- | ------------------ | ------ |
| 🔗 [Общие заголовки (MAG)](../../common-headers.md) | —   | —              | См. общую страницу | —      |

### Body
| Название                                                                          | Тип    | Обязательность | Описание                                         | Пример                                                             |

| Название      | Тип    | Обязательность | Описание                                                     | Пример          |
| ------------- | ------ | -------------- | ------------------------------------------------------------ | --------------- |
| `newPinToken` | String | Да             | Новый PIN-токен для установки пароля (метод `save_password`) | `eyJhbGciOi...` |

## Коды ответа
| Код ответа | Описание              | Причина                                                          |
| ---------- | --------------------- | ---------------------------------------------------------------- |
| `201`      | CREATED               | OTP подтверждён, клиент зарегистрирован, PIN-токен выдан         |
| `400`      | BAD_REQUEST           | Некорректное тело запроса                                        |
| `500`      | INTERNAL_SERVER_ERROR | Ошибка проверки OTP, регистрации клиента или создания PIN-токена |

🔗 *Все общие коды ошибок см. на странице [Общие ошибки (MAG)](../../common-errors.md).*

## Логика работы
1. **Приём и валидация:** MAG принимает запрос и валидирует поля `code`, `xOTPToken`, `agreements`.
2. **Проверка OTP:** Вызывает OTP Service (`/otp/v2/check`). При ошибке — ответ 500.
3. **Обработка соглашений:** Для каждого соглашения рассчитывает срок действия подписи (180 дней для подписанных, 999 лет для неподписанных) и при наличии подписанных обязательных соглашений отправляет метрику `SOPSign`.
4. **Регистрация клиента:** Вызывает Client API (`/v1/clients/registerByPhone`).
5. **Создание PIN-токена:** Вызывает Authentication Service (`/api/v3/create_new_pin_token`).
6. **Формирование ответа:** Возвращает `newPinToken` клиенту с кодом `201`.

## Request
```bash
curl -X POST "https://gateway.direct-pay.ru/api/v2/authentication/phase_otp" \
  -H "Content-Type: application/json" \
  -d '{
    "code": "111111",
    "xOTPToken": "eyJhbGciOi...",
    "agreements": [
      { "docID": 12345, "docTypeID": 1, "consentFlag": true }
    ]
  }'
```
