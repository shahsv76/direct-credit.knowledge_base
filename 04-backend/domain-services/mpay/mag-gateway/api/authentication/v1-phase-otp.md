# POST /api/v1/authentication/phase_otp (MAG)

| Тип запроса | Название метода | Описание метода                                                                                     | URL                                | Тип  |

| POST        | PhaseOTPShort   | Вторая фаза авторизации (v1): проверяет OTP-код, регистрирует клиента и формирует сессионный токен. | `/api/v1/authentication/phase_otp` | SYNC |

## Коды ответа
| Код ответа | Описание              | Причина                                                      |
| ---------- | --------------------- | ------------------------------------------------------------ |
| `201`      | CREATED               | OTP подтверждён, клиент зарегистрирован, сессия создана      |
| `400`      | BAD_REQUEST           | Некорректное тело запроса                                    |
| `500`      | INTERNAL_SERVER_ERROR | Ошибка проверки OTP, регистрации клиента или создания токена |

## Логика работы
1. **Приём и валидация:** MAG принимает запрос и валидирует поля `code`, `xOTPToken`, `agreements`.
2. **Проверка OTP:** Вызывает OTP Service (`/otp/v2/check`). При ошибке — ответ 500.
3. **Получение соглашений:** Запрашивает документы в Offer Service (`/v1/getCommonDocsInfoByDocTypes`) и рассчитывает даты действия подписи.
4. **Регистрация клиента:** Вызывает Client API (`/v1/clients/registerByPhone`), передавая код и подписанные соглашения.
5. **Создание сессии:** Вызывает Authorization Service (`/api/v1/create_token`) для генерации сессионного токена.
6. **Формирование ответа:** Возвращает сессионный токен клиенту с кодом `201`.

## Request
```bash
curl -X POST "https://gateway.direct-pay.ru/api/v1/authentication/phase_otp" \
  -H "Content-Type: application/json" \
  -d '{
    "code": "111111",
    "xOTPToken": "eyJhbGciOi...",
    "agreements": [
      { "docID": 12345, "docTypeID": 1, "consentFlag": true }
    ]
  }'
```
